# Retrieval v2 qualification

Final retained evidence for the closed #254/#260 qualification work. Hosted 1 GiB correctness completed, while its serial-session path is not a representative performance target. This is a trusted-devnet implementation and measurement report. Activation remains disabled by default; a local four-process run does not establish WAN capacity or a hardware minimum.

## C1: separate claims and counters

| Claim | Boundary |
| --- | --- |
| Committed content | Exact setup identity, canonical field/point encoding, complete Merkle path consumption and authenticated chained inclusion. A valid opening establishes consistency with the committed content, not that a user downloaded it. |
| Fresh response | Frozen session/assignment, future committed anchor and context-derived off-domain z. Old challenges cannot be substituted into new statements. Static inclusion components may be cached; zero/constant polynomial openings can legitimately repeat. Proof-byte uniqueness is neither required nor a delivery guarantee. |
| Authority | Frozen effective payee, transaction signer/EVM caller binding, authenticated ACK, explicit deputy authorization and funding-source restrictions. An observed public proof does not confer payment authority. |
| Storage assurance | Independent frozen assignment sampling without replacement. Population includes assigned user storage, parity and allocated padding; metadata is excluded. Organic requests, tiny sessions, cancellations and retries confer no audit exemption. |
| Bytes and payment | Requested payload, verified encoded coverage, billed coverage and transport bytes are separate quantities. A cryptographic proof never substitutes for client byte/hash verification before ACK. |
| Probability and capacity | Probability bounds use the declared fixed-unavailability/random-seed assumptions and actual achieved quota; operating load uses committed outcomes and fixed execution/memory budgets. Neither follows from verifier microbenchmarks. |

The trusted-devnet seed assumes non-grinding proposers. The current future block hash is not qualified as unbiased permissionless randomness. Fresh response does not rule out fast adaptive fetching, reconstruction or collusion. Statistical guarantees apply to each fixed assignment and epoch. Across T assignment-epochs, the union bound is min(1,Tp), where p is the per-assignment miss bound; no longer-horizon numerical assurance is claimed. Aggregate assignment work must fit its response window.

## Denominators and sampling

For an ordinary retrieval, every requested encoded blob is proved. It receives no constant-size sampling discount as the range grows. Sessions remain within one MDU and slot: K8 permits eight 128 KiB blobs per session. The untransformed 1 KiB fixture requires one proof; a 1 GiB logical payload requires 8,457 encoded blobs, 133 user MDUs and 1,064 sessions because each 32-byte field element carries 31 payload bytes. Its encoded proof/billing coverage is 1,108,475,904 bytes, distinct from the 1,073,741,824-byte logical payload. This arithmetic is not evidence that the download completed.

For storage audits, U=user_mdus*rows, with rows=64/K for StripeReplica. The C6 policy requests Q=min(U,132). With at least 10% of a fixed population unavailable and unbiased sampling, set bad=ceil(0.10U); the miss probability is C(U-bad,Q)/C(U,Q), or zero when Q>U-bad, bounded by 0.9^Q. Q=132 gives an upper bound of 9.12034456e-7; cap 64 gives 0.00117901846. At 1% unavailable, the analogous quota is 1,375 for a 10^-6 bound. One missing blob out of 8,192 has only 132/8,192=1.611328125% detection probability at Q=132. These are different threat targets. Sampling is without replacement within one obligation, not across all future epochs: a later challenge may select the same blob, but its response must verify against the new frozen challenge context. Permanently excluding previously sampled blobs would eventually exhaust the population and make the remaining positions predictable.

The retained C6 local profile has three assignments, each U=32 and Q=32: 96 actual samples per epoch. It tests complete coverage of those small populations; the exact theoretical miss bound for fixed unavailable content is zero when U=Q=32. It does not demonstrate 132 issued samples for a larger assignment or the full admitted 64-assignment workload. Larger inventories require their own aggregate deadline qualification; the owning bounded keeper tests establish finite admission/snapshot work, not that a larger network meets the measured operating envelope.

## Independent correctness evidence

The retained original/current counterexamples cover unrelated proof signers, missing payee pins, zero-fee cleanup, surplus Merkle siblings, changed setup trailers, skipped reinitialization validation, caught child EVM rollback, insufficient child crypto gas, malformed HTTP 200 transaction results and durable-proof corruption. Safe assertions fail on the original behavior and pass on the corrected behavior. The sufficient-gas EVM control succeeds in both. Original dependency/source/library identity and adaptations are explicit; an initial disk-exhausted compilation is excluded.

Historical native/C ABI, keeper and EVM cases are local function/application executions; they are not all four-validator submissions. The network cases are enumerated in the settlement row below.

These comparisons complement the owning v2 transcript, boundary, migration, funding, replay, rollback, browser failure and setup-startup tests. They do not derive correctness from four copies of the same code agreeing or from a fast verifier matching an old verifier.

## Measurements

- Final mixed keeper comparison: five interleaved observations, six fresh sessions / 52 openings per iteration. Verification median 274.638 to 45.209 ms (6.075x), generation 6,485.806 to 1,761.299 ms (72.84% reduction), both ranges disjoint. Gas unchanged at 26,155,844. Go allocation increases by a bounded 22,976 bytes per batch while allocations fall by 92. Whole-process RSS ranges overlap; this is not retained heap.
- Settlement: each normal-mint mode completed six sessions / 22 openings with exactly 392 stake debits, 246 payouts and 146 burns. Both use slot zero for K8/K2. Issuance is independently reconciled rather than disabled. The adversarial network mode adds five committed expected failures: unrelated signer and wrong system-z for each layout, then a later native-message failure. Four idempotent retries repeat proof and confirmation for each layout, preserving retrieval state. All four validators agree on signed transaction outcomes and gas, and persistent restart checks pass.
- Sustained proof acceptance: 1,395 session transactions were offered during the 900-second window; 1,071 committed inside it, while the full drain reached 1,203 eventual commits and 192 queue-full offers were not submitted. Each transaction carried 32 fresh challenge-bound openings for one K2 session, so the 1,071 in-window commits represent 34,272 openings. All four validators agree on outcomes/gas through block 2,806. The 2 transactions/s step admitted all 360 offers with 3.980 ms offer-to-dispatch p95 and observed 357 successful results in 180 seconds; this offered 64 openings/s and observed 63.4667 openings/s for that one step. The 4/s step observed 397 results, filled the 128-entry queue, and left 135 results for drain. The scheduler finished in 960.621 seconds. All step/validator conservative Commit p95 bounds establish the fixed 700 ms budget; worst retained bound is 640.318 ms. Validator lifetime peak RSS is 553.927–589.988 MB, below 2 GiB. Blocks reach the 64M wanted-gas ceiling; three 32-opening transactions alone reserve 60M, and four would exceed the block limit even at measured used gas. This supports gas-limited saturation with 2 offered session transactions/s as the highest stable tested rate, within the measured step. Original raw records show all measurement epochs 21–28 finalized with 96/96 audit samples and zero misses before interruption. The disk guard stopped the later epoch-29 audit-boundary wait during the postlude, so original whole-run status remains failed. Separate recovery accepted the remaining 44 samples after a pause and reached 96/96; it is supplementary evidence and does not replace uninterrupted measurement coverage. The Commit metric excludes transition tail and next-round scheduling; it is not total block cadence. Blocks 2090–2761 contain the 1,071 in-window commits over 672 blocks (1.59375 transactions/block, 1.19 transactions/s). Only 1,068 completion-plus-state-query observations finish inside that window; the remaining three queries cross its boundary. Including drain, blocks 2090–2806 contain all 1,203 transactions over 717 blocks (1.6778 transactions/block). At the stable step, 357 observed completions / 180 seconds = 1.9833 session transactions/s; arithmetic projections are 7,140/hour and 171,360/day. The offered rate of 2/s projects to 7,200/hour and 172,800/day. These projections are not hour/day-duration measurements. Prepared-proof transaction acceptance is not generation, completed delivery or paid lifecycle throughput.
- Delivered bytes: hosted streamed 1 GiB correctness completed; performance remains unqualified. The first run reverted without a retained receipt, so its precise cause remains unknown. A native regression independently demonstrated ACK gas growth at height 127 to 128; browser transactions now estimate before broadcasting and add ceil(20%) plus 10,000 gas. Bounded failed-transaction diagnostics are retained on subsequent failures. The second run stopped after 208 proof requests when three missed storage-audit epochs caused slot repairs: its short-smoke harness had disabled background proving. The browser correctly refused the changed assignment. Merged PR #285 enables the existing provider storage prover for streamed runs. The third run, 34267852521 at ed72c70e, stopped with a Chromium no-space output write after 904 proof requests; its [incomplete raw evidence](../bench/retrieval_session_capacity/delivery-final-260/large-incognito-failed.json.gz) does not establish completed delivery. PR #288 reuses the existing fresh disk-backed browser profile and adds the complete 1 GiB OPFS preflight before funding. Replacement run 34281520872 completed: the [retained summary](../bench/retrieval_session_capacity/delivery-final-260/large-persistent-success.json.gz) verifies the full file hash and 1,064 terminal sessions across 8,457 blobs. Retrieval took 9,475,070 ms. The owner subsequently retired this serial paid-session workload as a representative performance qualification.

## Delivery observability retained; serial large-file performance not qualified

The completed hosted run reported its retrieval summary only at completion. Its 9,475,070 ms retrieval interval (including final stream/hash, excluding upload and terminal census) yields approximately 110.67 KiB/s. It had no periodic retrieval heartbeat or stalled-progress watchdog, so live job status could not establish forward progress. Successful hash and terminal-session census establish correctness for that run, not representative download latency.

The production `useFetch` caller processes one MDU at a time: normally eight K8 sessions per wave, across 133 MDUs for this file. Fetch, verification and output writes are sequential within each wave. Flush and owner ACK precede settlement; settlement already overlaps up to four distinct payee groups. These code facts identify measurement boundaries, not a measured bottleneck.

PR #288 implemented 60-second substantive progress heartbeats, a 10-minute no-progress watchdog and an absolute retrieval deadline. It merged as `5b1d77d1` after all 28 checks and clean current-head independent/hosted reviews. The instrumented 15.5 MiB [run 34296651542](https://github.com/Polynomialstore/polystore/actions/runs/34296651542) passed in 143,874.596 ms (110.32 KiB/s). Its [retained phase baseline](../bench/retrieval_session_capacity/delivery-final-260/README.md#instrumented-155-mib-baseline) records browser verification at 61.052s, challenge waits at 19.658s, transport at 18.492s, ACK/settlement at 30.143s and decode/write/flush at 0.276s. The observed rate projects about 158.4 minutes for 1 GiB, consistent with the completed run. These measurements are retained diagnostic context for the retired path, not an active optimization or rerun gate.

A [bounded fixed-base WASM comparison](../bench/retrieval_session_capacity/delivery-final-260/rejected-fixed-base/README.md) rejected the candidate: 3/6 MiB tables regressed, while 12 MiB results ranged from 4% slower to 3% faster and an independent repeat gave only 0.7% benefit. The experimental code was removed. Draft PR #289's two-window overlap was also closed without merge because it optimized the retired serial-session workload.

No further run of the retired 1,064-session 1 GiB workload is planned. [#290](https://github.com/Polynomialstore/polystore/issues/290) owns the immediate milestone: committed native K8 chain throughput with concurrent sessions/providers and normal audits. [#291](https://github.com/Polynomialstore/polystore/issues/291) owns the desired production contract and implementation for one native large logical session with sampled KZG challenges and authenticated full-byte integrity; that path is not implemented or qualified. Its future proof-acceptance result must remain separate from end-to-end download performance. Set a download target only after measuring a realistic deployment.

## Reproduction and disposition

Use the existing driver, frozen source/binary/library/setup hashes, new task-owned homes, fixed workload profile and raw artifacts. Do not reuse a running chain home or silently change budgets after observing the candidate. Full source/build commands, measurement boundaries and dispersion belong beside each artifact. Legacy hosted delivery artifacts identify the workflow run and checkout/harness source only. The new instrumented small summary also records actual executable/served-WASM hashes and available native link-candidate hashes, with the latter explicitly not a loaded-image attestation. Do not substitute these source identities for the separately pinned local benchmark binaries.

Local infrastructure is a shared Apple workstation with four co-located validator processes. `INFRASTRUCTURE_UNAVAILABLE: local storage`: free local disk does not satisfy the 1 GiB fixture's 12 GiB guard. The actual fallback is the existing GitHub-hosted Linux workflow, with its declared Cargo/Go/npm caches; no dedicated runner or persistent runner cache is claimed. Initial local compilation failures and obsolete task-cache cleanup are retained separately from successful test evidence. The first final C6 attempt stopped during proof preparation at its 768 MiB disk floor (759,275,520 bytes observed), before measurement. Its guard and logs are retained; it is not a capacity result. A fresh-home retry preserves the exact runtime/harness and measurement budgets with a higher 2 GiB starting-space requirement. No independent four-host or WAN claim is made.

#258's measured generator optimization is selected. #251 cross-provider aggregation and #259 broader control-plane changes remain deferred; neither is required for these claims, and no new channels, caches or dashboard are introduced. #254/#260 remain closed as historical work under the revised scope. #290 owns the current chain-throughput gap and #291 owns the sampled large-session protocol; neither blocks publication of this historical evidence.
