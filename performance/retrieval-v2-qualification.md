# Retrieval v2 qualification

Draft pending successful hosted 1 GiB retrieval and final review. This is a trusted-devnet implementation and measurement report. Activation remains disabled by default; a local four-process run does not establish WAN capacity or a hardware minimum.

## C1: separate claims and counters

| Claim | Boundary |
| --- | --- |
| Committed content | Exact setup identity, canonical field/point encoding, complete Merkle path consumption and authenticated chained inclusion. A valid opening establishes consistency with the committed content, not that a user downloaded it. |
| Fresh response | Frozen session/assignment, future committed anchor and context-derived off-domain z. Old challenges cannot be substituted into new statements. Static inclusion components may be cached; zero/constant polynomial openings can legitimately repeat. Proof-byte uniqueness is neither required nor a delivery guarantee. |
| Authority | Frozen effective payee, transaction signer/EVM caller binding, authenticated ACK, explicit deputy authorization and funding-source restrictions. An observed public proof does not confer payment authority. |
| Storage assurance | Independent frozen assignment sampling without replacement. Population includes assigned user storage, parity and allocated padding; metadata is excluded. Organic requests, tiny sessions, cancellations and retries confer no audit exemption. |
| Bytes and payment | Requested payload, verified encoded coverage, billed coverage and transport bytes are separate quantities. A cryptographic proof never substitutes for client byte/hash verification before ACK. |
| Probability and capacity | Probability bounds use the declared fixed-unavailability/random-seed assumptions and actual achieved quota; operating load uses committed outcomes and fixed execution/memory budgets. Neither follows from verifier microbenchmarks. |

The trusted-devnet seed assumes non-grinding proposers. The current future block hash is not qualified as unbiased permissionless randomness. Fresh response does not rule out fast adaptive fetching, reconstruction or collusion. Statistical guarantees apply to each fixed assignment and epoch. Across T assignment-epochs, the union bound is min(1,Tp), where p is the per-assignment miss bound; no longer-horizon numerical assurance is claimed. Aggregate assignment work must fit its response window.

## Denominators and sampling

For an ordinary retrieval, every requested encoded blob is proved. It receives no constant-size sampling discount as the range grows. Sessions remain within one MDU and slot: K8 permits eight 128 KiB blobs per session. The untransformed 1 KiB fixture requires one proof; a 1 GiB logical payload requires 8,457 encoded blobs, 133 user MDUs and 1,064 sessions because each 32-byte field element carries 31 payload bytes. Its encoded proof/billing coverage is 1,108,475,904 bytes, distinct from the 1,073,741,824-byte logical payload. This arithmetic is not evidence that the download completed.

For storage audits, U=user_mdus*rows, with rows=64/K for StripeReplica. The C6 policy requests Q=min(U,132). With at least 10% of a fixed population unavailable and unbiased sampling, set bad=ceil(0.10U); the miss probability is C(U-bad,Q)/C(U,Q), or zero when Q>U-bad, bounded by 0.9^Q. Q=132 gives an upper bound of 9.12034456e-7; cap 64 gives 0.00117901846. At 1% unavailable, the analogous quota is 1,375 for a 10^-6 bound. One missing blob out of 8,192 has only 132/8,192=1.611328125% detection probability at Q=132. These are different threat targets. Sampling is without replacement within one obligation, not across all future epochs: a later challenge may select the same blob, but its response must verify against the new frozen challenge context. Permanently excluding previously sampled blobs would eventually exhaust the population and make the remaining positions predictable.

The retained C6 local profile has three assignments, each U=32 and Q=32: 96 actual samples per epoch. It tests complete coverage of those small populations; the exact theoretical miss bound for fixed unavailable content is zero when U=Q=32. It does not demonstrate 132 issued samples for a larger assignment or the full admitted 64-assignment workload. Larger inventories require their own aggregate deadline qualification; the owning bounded keeper tests establish finite admission/snapshot work, not that a larger network meets the measured operating envelope.

## Independent correctness evidence

The retained original/current counterexamples cover unrelated proof signers, missing payee pins, zero-fee cleanup, surplus Merkle siblings, changed setup trailers, skipped reinitialization validation, caught child EVM rollback, insufficient child crypto gas, malformed HTTP 200 transaction results and durable-proof corruption. Safe assertions fail on the original behavior and pass on the corrected behavior. The sufficient-gas EVM control succeeds in both. Original dependency/source/library identity and adaptations are explicit; an initial disk-exhausted compilation is excluded.

Historical native/C ABI, keeper and EVM cases are local function/application executions; they are not all four-validator submissions. The network cases are enumerated in the settlement row below.

These comparisons complement the owning v2 transcript, boundary, migration, funding, replay, rollback, browser failure and setup-startup tests. They do not derive correctness from four copies of the same code agreeing or from a fast verifier matching an old verifier.

## Measurements

- Final mixed keeper comparison: five interleaved observations, six fresh sessions / 52 openings per iteration. Verification median 274.638 to 45.209 ms (6.075x), generation 6,485.806 to 1,761.299 ms (72.84% reduction), both ranges disjoint. Gas unchanged at 26,155,844. Go allocation increases by a bounded 22,976 bytes per batch while allocations fall by 92. Whole-process RSS ranges overlap; this is not retained heap.
- Settlement: each normal-mint mode completed six sessions / 22 openings with exactly 392 stake debits, 246 payouts and 146 burns. Both use slot zero for K8/K2. Issuance is independently reconciled rather than disabled. The adversarial network mode adds five committed expected failures: unrelated signer and wrong system-z for each layout, then a later native-message failure. Four idempotent retries repeat proof and confirmation for each layout, preserving retrieval state. All four validators agree on signed transaction outcomes and gas, and persistent restart checks pass.
- Sustained proof acceptance: the full 900-second offered window finished with 1,395 offers: 1,203 committed proofs with independently checked pinned state, 192 queue-full offers not submitted, no unknown outcomes. All four validators agree on outcomes/gas through block 2,806. The 2/s step admitted all 360 offers with 3.980 ms offer-to-dispatch p95 and observed 357 successful results in 180 seconds; the 4/s step observed 397 results, filled the 128-entry queue, and left 135 results for drain. The scheduler finished in 960.621 seconds. All step/validator conservative Commit p95 bounds establish the fixed 700 ms budget; worst retained bound is 640.318 ms. Validator lifetime peak RSS is 553.927–589.988 MB, below 2 GiB. Blocks reach the 64M wanted-gas ceiling; three 32-opening proof transactions alone reserve 60M, and four would exceed the block limit even at measured used gas. This supports gas-limited saturation with 2/s as the highest tested stable offered rate, within the measured window. Original raw records show all measurement epochs 21–28 finalized with 96/96 samples and zero misses before interruption. The disk guard stopped the later epoch-29 audit-boundary wait during the postlude, so original whole-run status remains failed. Separate recovery accepted the remaining 44 samples after a pause and reached 96/96; it is supplementary evidence and does not replace uninterrupted measurement coverage. The Commit metric excludes transition tail and next-round scheduling; it is not total block cadence. Across the full offered window, blocks 2090–2761 contain 1,071 committed workload proofs over 672 blocks (1.59375 proofs/block, 1.19 proofs/s over the 900-second window). Only 1,068 completion-plus-state-query observations finish inside that window; the remaining three queries cross its boundary. Including drain, blocks 2090–2806 contain all 1,203 proofs over 717 blocks (1.6778 proofs/block). At the stable step, 357 observed completions / 180 seconds = 1.9833 sessions/s; arithmetic projections are 7,140/hour and 171,360/day. The offered rate of 2/s projects to 7,200/hour and 172,800/day. These projections are not hour/day-duration measurements. Proof acceptance is not completed delivery or paid lifecycle throughput.
- Delivered bytes: PENDING successful hosted streamed 1 GiB run. The first run reverted without a retained receipt, so its precise cause remains unknown. A native regression independently demonstrated ACK gas growth at height 127 to 128; browser transactions now estimate before broadcasting and add ceil(20%) plus 10,000 gas. Bounded failed-transaction diagnostics are retained on subsequent failures. The second run stopped after 208 proof requests when three missed storage-audit epochs caused slot repairs: its short-smoke harness had disabled background proving. The browser correctly refused the changed assignment. Merged PR #285 enables the existing provider storage prover for streamed runs. The third run, 34267852521 at ed72c70e, stopped with a Chromium no-space output write after 904 proof requests; its [incomplete raw evidence](../bench/retrieval_session_capacity/delivery-final-260/large-incognito-failed.json.gz) does not establish completed delivery. Replacement run 34281520872 remains pending; large delivery qualification is still open.

## Reproduction and disposition

Use the existing driver, frozen source/binary/library/setup hashes, new task-owned homes, fixed workload profile and raw artifacts. Do not reuse a running chain home or silently change budgets after observing the candidate. Full source/build commands, measurement boundaries and dispersion belong beside each artifact. Hosted delivery artifacts identify the workflow run and checkout/harness source; they do not record the running executable, native-library or WASM binary hashes. Do not substitute these source identities for the separately pinned local benchmark binaries.

Local infrastructure is a shared Apple workstation with four co-located validator processes. `INFRASTRUCTURE_UNAVAILABLE: local storage`: free local disk does not satisfy the 1 GiB fixture's 12 GiB guard. The actual fallback is the existing GitHub-hosted Linux workflow, with its declared Cargo/Go/npm caches; no dedicated runner or persistent runner cache is claimed. Initial local compilation failures and obsolete task-cache cleanup are retained separately from successful test evidence. The first final C6 attempt stopped during proof preparation at its 768 MiB disk floor (759,275,520 bytes observed), before measurement. Its guard and logs are retained; it is not a capacity result. A fresh-home retry preserves the exact runtime/harness and measurement budgets with a higher 2 GiB starting-space requirement. No independent four-host or WAN claim is made.

#258's measured generator optimization is selected. #251 cross-provider aggregation and #259 broader control-plane changes remain deferred; neither is required for these claims, and no new channels, caches or dashboard are introduced. #254/#260 stay open until the pending measurement/delivery/report gates are satisfied or the owner explicitly accepts a narrower target.
